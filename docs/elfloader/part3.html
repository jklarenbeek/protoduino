These came out of reviewing the UART and serial layers as a base for the loader. Each was checked by running protoduino's real sources under protosim, except where marked as read. None has been applied. Four are defects; the rest are small.

Proposed changes

/* 1. uart_private_impl.h, openex(): remember which divisor is in force */
  uint8_t  samples = 8;                                   /* double speed: clock / 8 */
  uint16_t baud_setting = (F_CPU / 4 / baud - 1) / 2;
  __UCSRA__ = 1 << __U2X__;
  if (((F_CPU == 16000000UL) && (baud == 57600)) || (baud_setting > 4095)) {
    baud_setting = (F_CPU / 8 / baud - 1) / 2;
    __UCSRA__ = 0;
    samples = 16;                                         /* normal speed: clock / 16 */
  }
  ...
  CC_TMPL_VAR(baudrate) = F_CPU / ((uint32_t)samples * (baud_setting + 1));

/* 2. uart_private_impl.h, close(): leave the caller's interrupt state alone */
void CC_TMPL_FN(close)(void)
{
  CC_ATOMIC_RESTORE()
  {
    CC_TMPL_VAR(baudrate) = 0;
    __UCSRB__ &= ~(_BV(__RXEN__) | _BV(__TXEN__) | _BV(__RXCIE__) | _BV(__UDRIE__));
  }
}

/* 3. serial_private_impl.h, flush(): poll the port when interrupts are OFF */
  if (bit_is_clear(SREG, SREG_I))
  {
    if (!CC_TMPL2_FN(tx_is_ready)())
      return cnt;
    CC_TMPL2_FN(tx_write8)(ringb8_get(&VAR_TX));
    return cnt - 1;
  }
  CC_TMPL2_FN(tx_enable_int)();
  return cnt;
  • 4. Replace docs/loader.md with a short page that points here, and mark the README entry as a design, not a feature.
  • 5. Delete the dead branch. If frame errors are wanted later, report them from the receive interrupt, where the flags are read before the data register and are valid; put it behind UART_CONF_REPORT_FRAME_ERRORS, default off, so behaviour stays as it is.
  • 6. One paragraph in uart_private_header.h: use the callbacks with interrupts on, or the polled calls with interrupts off, never both.
  • 7. Add UART_CONF_ISR, default 1. With 0, the handlers, the callback setters and the receive-interrupt enable in openex() are left out, and the bootloader can use the same template.
  • 8. A relative library reference in platformio.ini.
  • 9. Return ERR_SERIAL_BAUD for a zero rate; put the message behind a verbose-build switch.

Findings from my first review that testing withdrew

They are listed so the record is straight. The polled receive calls do work after open() when interrupts are off. rx_clear_errors() does clear an overrun under simavr; on a real chip those flags are read-only and clear when the data register is read, so the call is harmless there. The transmit path through the data-register-empty interrupt is sound: 18 bytes went out in 19 handler calls. The 57600 special case is the deliberate Arduino-compatible behaviour. The read-modify-write on the control register can at worst cause one extra interrupt that switches itself off.

9.1End to end in simulation

9.2On the host

The same core, compiled natively, was fed real files in chunks of random size and its output compared with avr-objcopy.

  • Flash and EEPROM images identical for the test program built for ATmega328P, ATmega2560 and ATtiny85; identical for example 12, for its stripped form, for one-byte-at-a-time feeding, and for the 106 KB image.
  • The signature bytes extracted from the three files were those of the three parts.
  • Refused as designed: a file for another family (0x81), an image larger than the window (0x83), a non-ELF file, a relocatable .o and an x86-64 object (all 0x80). A truncated file leaves the core waiting for more.
  • A module was accepted in its own slot and refused in another; the firmware was refused in a module slot.

9.3Not verified

  • Anything on hardware, including fuse and lock-bit settings and real programming times.
  • Loss of power during an update. The transaction argument in 4.4 is by construction.
  • The ATtiny path: it has never executed.
  • The image CRC check at start-up, the information reply, and the service entry on the ATmega2560.
  • The module layer beyond linking and the window check.

9.4Test plan from here

  • Host unit tests in CI for the core, with the files above as fixtures, and a fuzzer on elfld_write(). The core is small, pure C and takes untrusted input, which is the ideal fuzzing target.
  • protosim end to end per supported part, once P1 to P4 exist, with the oracle comparison as the pass criterion.
  • Hardware: an Uno and a Mega 2560, with an ISP programmer at hand for fuses. A relay on the supply to cut power at random points of an update, hundreds of times, checking that the board always answers afterwards.

Risks

  • Size. The 1 KB boot section may stay out of reach. The design does not depend on it; a 2 KB section costs the application 1 KB.
  • ATtiny recovery. Without hardware protection for the loader's pages, a faulty application can destroy it. The claim for these parts is deliberately weaker.
  • Exact binding. Convenient while developing, awkward for distributing modules. The table scheme is the answer and costs flash.
  • Interrupt blackout. Flash writes at run time stall the system for milliseconds at a time.
  • Old compiler. All sizes are from avr-gcc 7.3.0. A newer one may be better or worse.

Open questions

  • Which small part is meant by “ATtiny8”? The answer decides whether the small-frame transport is needed early.
  • Should updates be authenticated, and if so with what? A keyed hash costs several hundred bytes.
  • Which binding scheme is the default for modules: exact or table?
  • Should the loader wait after every reset, or only on request? It changes start-up time by seconds.
  • Where should the bootloader's build live, given that it cannot be under src/?

BReproducing the measurements

Everything is in docs/elfloader/prototype/. It needs gcc-avr, avr-libc, libelf-dev and protosim built with its simavr submodule.

# core on the host, against a file built with avr-gcc
gcc -std=c99 -O2 -DELFLD_FEAT_EEPROM=1 -DELFLD_FEAT_SIGNATURE=1 -o host_test host_test.c elfld.c
./host_test app.elf 5 out.bin
avr-objcopy -O binary -j .text -j .data app.elf ref.bin && cmp out.bin ref.bin

# the bootloader, and its size
./build.sh m328 atmega328p 0x7800
./build.sh m2560 atmega2560 0x3F000 -DELFBOOT_FEAT_SERVICE=1

# end to end in simavr
S=../../../../protosim/libraries/simavr/simavr
gcc -O2 -o sim_harness sim_harness.c -I$S/sim -I$S/sim/avr \
    $S/obj-x86_64-linux-gnu/libsimavr.a -lelf -lm -lpthread
./sim_harness atmega328p out/m328.elf app.elf --corrupt 3 --drop-ack 5

Recorded outputs are in results-sizes.txt and results-tests.txt. The UART and serial findings of section 7 come from probes/uart_probe.c and probes/serial_flush_probe.c, built against protoduino's own sources and run with protosim --uart0-in … --uart0-out ….
